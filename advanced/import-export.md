# 导入导出与分享工作流

你可以将已调优好的采集规则导出为独立文件，随时用于**本地备份、多电脑迁移，或直接发送给同事团队复用**。

在使用前，必须先厘清**两种不同的文件格式**——它们导出和导入的入口各自独立，不能跨页面混用：

| 文件类型                         | 包含内容                                                     | 导出入口               | 导入入口                   |
| :------------------------------- | :----------------------------------------------------------- | :--------------------- | :------------------------- |
| **工作流文件**<br>_(单品规则)_   | 仅包含采集规则本身（字段定义、点击与翻页步骤）               | 「主工作台」卡片右下角 | 「主工作台」右上角「导入」 |
| **任务包文件**<br>_(全家桶预设)_ | 包含工作流规则 **+** 批量目标网址清单 **+** 定时运行周期预设 | 「定时任务」卡片操作栏 | 「定时任务」右上角「导入」 |

::: warning ⚠️ 两种文件不可混淆导入
从哪个页面导出的文件，就必须回到哪个页面导入。  
若在「定时任务」页误选了工作流文件，系统会明确提示：

> _导入失败：第 N 条不是任务包（若这是工作流文件，请到工作流列表导入）_

此时无需慌张，文件本身没有任何损坏，只需**切换至「主工作台」重新导入**即可。
:::

## 一、导出工作流文件

**适用场景**：将一套通用的采集规则分享给同事，由对方自行在各自的网页上启动执行。

1. 进入侧边栏「**主工作台**」。
2. 找到对应的采集规则卡片，点击卡片底部右侧的**下载图标**（鼠标悬停提示「下载此工作流」）。
3. 浏览器会自动下载一个 `.json` 文件至本地默认下载目录，文件名即为该工作流的名称。

---

## 二、导出定时任务包

**适用场景**：需要将一套完整的计划任务（包含几百条商品链接清单和每天定时运行的配置）整体打包迁移至另一台电脑长期挂机。

1. 进入侧边栏「**定时任务**」。
2. 找到对应的任务卡片，点击操作栏中的「**下载任务包**」按钮。
3. 系统将导出包含任务名称、网址列表、触发频率及启用开关状态的综合任务包。

::: tip 提示「工作流已不存在，无法下载」怎么办？
若任务引用的底层工作流被误删，任务包将失去执行核心而无法导出。点击「编辑」为该任务重新关联一个现存有效的工作流后，即可正常导出。
:::

---

## 三、导入操作指南

两个导入入口均位于对应页面右上角，支持**单文件批量导入**（一份合规文件内包含多条规则时，系统支持一次性全部载入）：

- **导入工作流**：在「主工作台」右上角点击「**导入**」→ 选择工作流 `.json` 文件。成功后提示：「_已导入 N 条工作流_」。
- **导入任务包**：在「定时任务」右上角点击「**导入**」→ 选择任务包 `.json` 文件。成功后提示：「_已导入 N 个任务_」。

## 四、原子校验机制与常见报错排查

::: tip 先检查格式，再逐条导入
导入前会检查文件中的各条内容；如果有一条格式不符，不会开始写入。通过检查后会逐条保存；如果保存途中出错，前面已导入的内容可能仍然保留。重新导入前请先检查列表，避免重复。
:::

导入失败时的提示词对照与解决对策：

| 错误提示                              | 根本原因                                   | 正确应对方案                                 |
| :------------------------------------ | :----------------------------------------- | :------------------------------------------- |
| **导入失败：第 N 条不是任务包**       | 在「定时任务」页误选了工作流文件           | 换到「主工作台」右上角重新导入               |
| **导入失败：文件不是有效的 JSON**     | 选错了本地文件（如选成了文本或图片）       | 重新选择九头虫 Agent 导出的标准 `.json` 文件 |
| **导入失败：第 N 条不是有效的工作流** | 文件在传输过程中损坏，或人为修改了内部字段 | 联系源头重新导出一份未篡改的原文件           |
| **文件中没有可导入的内容**            | 文件结构合法但内容为空                     | 仅为提醒，确认源文件内是否包含已保存的规则   |

## 五、两个关键机制与工作流更新指引

### 1. 机制一：只增不覆，不自动去重

**导入操作永远执行新增（Append），不会覆盖已有同名规则**。  
若同一份文件连续导入两次，主工作台中会出现两张名字一模一样的卡片。

导出的工作流不包含本机「数据存储」里的数据集；如果工作流还依赖其他工作流、本地文件或飞书配置，换电脑后需要检查这些依赖是否仍然可用。导入后先用少量数据试跑。

> **💡 如何规范更新已有工作流？**
> 如果团队同步了一版修复后的新工作流：
>
> 1. 先认准旧卡片采集的目标网址，导入后好和新的那张区分开（两张卡片名字会一模一样）。
> 2. 点击右上角「**导入**」，选新版本的工作流文件。新卡片会排在列表**最上面**。
> 3. 在新卡片上点「**手动启动**」试跑一次，确认采集合格后，到旧卡片最右边点「**更多操作**」→「**删除**」。

### 2. 机制二：任务包连带“启用状态”同步复原

导出任务包时若右上角开关处于**开启**状态，导入到新电脑后**同样默认保持开启**！

- 如果该任务设为“每 5 分钟跑一次”，导入后几分钟内可能就会自动唤起浏览器执行。
- **安全建议**：导入任务包后，**第一时间去「定时任务」列表中确认该卡片的开关状态**，若暂时无需自动运行请手动关闭。

## 六、团队共享与数据安全边界

将工作流文件发送给第三方或团队成员时，可对照以下安全清单：

| 资产类型                       | 是否会随文件导出 | 安全性说明                                                 |
| :----------------------------- | :--------------: | :--------------------------------------------------------- |
| **采集步骤与字段名称**         |    ✅ 会导出     | 包含你的业务逻辑提取要求。                                 |
| **初始目标网页网址**           |    ✅ 会导出     | 包含你抓取的目标网站链接（内部私有系统请留意脱敏）。       |
| **数据存储中的采集结果**       | 通常不随工作流导出 | 工作流不是数据备份；但规则里可能包含你主动写入的内容。 |
| **飞书 App Secret / AI 密钥** | 不作为配置自动打包 | 如果你把密钥、网址或业务数据直接写进需求或工作流步骤，导出文件仍可能包含它们。分享前请检查。 |
