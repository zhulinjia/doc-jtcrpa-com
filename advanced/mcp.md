# 九头虫 MCP 连接指南

接入九头虫 MCP 后，可以在 Codex 或腾讯 WorkBuddy 里查看本机浏览器的标签页、生成和运行采集工作流，以及读取已保存的数据。每个 AI 客户端添加一次「通用 MCP 配置」，就能按名称使用已接入的 Chrome、Edge 和 Firefox 浏览器配置。

## 开始前

- 在 Windows 或 macOS 上使用 Chrome、Edge 或 Firefox，并安装带有「**MCP 连接**」入口的九头虫 Agent。[安装与首次使用](/guide/install)
- 在同一台电脑上安装 Node.js 20.19.0 或更高版本，并使用支持本机 MCP（STDIO）的 AI 客户端。[下载 Node.js](https://nodejs.org/zh-cn/download)
- 本文的通用配置和连接撤销步骤适用于桥接器 0.12.3 或更新版本，以及配套的扩展。已有旧版桥接器时，按下面的安装步骤更新。
- 如果使用 ChatGPT 桌面端，请在本机 Codex 会话中完成接入。只有远程 MCP 网址入口的客户端无法直接使用这份本机配置。

## 1. 连接浏览器与本机程序

1. 在要接入的浏览器里，点击九头虫图标打开侧边栏，然后从底部打开「**设置菜单** → **MCP 连接**」。
2. 在「**安装桥接器**」区域点击「**复制安装命令**」。Windows 打开 PowerShell，macOS 打开「终端」，粘贴并运行。桥接器在同一台电脑上安装一次即可。
3. 打开「**开启 MCP 连接**」开关。如果浏览器弹出权限请求，允许本机通信。开启后，这份浏览器配置可供已接入九头虫通用 MCP 的本机 AI 客户端使用。
4. 在「**接入外部 AI**」区域点击「**复制接入命令**」，保持目标浏览器打开，在终端运行整条命令。已显示「**复制通用 MCP 配置**」时，可以直接配置 AI 客户端。

回到「**MCP 连接**」页，确认显示「**浏览器与本机程序已连接**」。需要区分多个浏览器配置时，在「**浏览器名称（选填）**」填入易认的名字，例如「店铺 A」，再点「**保存**」。

## 2. 添加到 AI 客户端并验证连接 {#_2-添加到-codex-并验证连接}

在扩展的「**MCP 连接**」页点击「**复制通用 MCP 配置**」。每个客户端添加一次 `jtcrpa` 服务，保留生成的启动命令和完整参数。按正在使用的客户端选择 [Codex](#codex) 或 [WorkBuddy](#workbuddy)。

### 添加到 Codex {#codex}

- **在桌面端手动添加。** 在 ChatGPT 桌面端打开「**设置 → MCP 服务器 → 添加服务器**」（英文界面为 **Settings → MCP servers → Add server**），选择 **STDIO**，按刚才复制的配置填写名称、命令和参数。保存后按客户端提示重启。[Codex MCP 配置说明](https://developers.openai.com/codex/mcp)
- **让本机 Codex 添加。** 把配置粘贴给 Codex，并说明「请把这份九头虫通用 MCP 配置添加到当前 Codex 的 MCP 设置中，保留其他已有服务」。配置保存后，重新打开客户端以加载配置。

### 添加到腾讯 WorkBuddy {#workbuddy}

1. 打开同一台电脑上的 WorkBuddy 桌面端，点击左侧「**专家·技能·连接器**」，切到「**连接器**」页签。
2. 点击右上方「**自定义连接器**」，在「**MCP 服务管理**」里点击「**添加 MCP**」。
3. 在编辑框里添加刚从扩展复制的通用配置。空配置可以直接替换成整份内容。已有配置时，把 `jtcrpa` 条目合并到原有的 `mcpServers` 里，保留其他连接器。点击「**保存**」。
4. **完全退出 WorkBuddy，再重新打开。** 回到「**自定义连接器 → MCP 服务管理**」，找到 `jtcrpa`，点击「**信任**」。等服务名旁的状态点变绿，并显示已启用的工具数量。[WorkBuddy 信任授权说明](https://cloud.tencent.com/document/product/1831/139964)
5. 在 WorkBuddy 点击「**新建任务**」。如果需要为本次任务开启连接器，点击输入框左下角「**+ → 连接器**」，启用 `jtcrpa`，再按下方步骤验证浏览器连接。[WorkBuddy 连接器说明](https://cloud.tencent.com/document/product/1831/134525)

如果 WorkBuddy 已有同名的浏览器专用配置，先备份旧配置，再把原来的 `jtcrpa` 条目换成通用配置中的同名条目。

### 验证连接 {#verify-connection}

在加载配置后的会话中发送下面这句话。

> 使用九头虫 MCP 检查连接，告诉我选中的浏览器配置名，并列出它的标签页和当前标签页。

看到目标配置的标签页，说明客户端已连通。只有一份配置确认在线、其余配置均已确认离线时，新任务可直接使用这一份。有多个候选在线或状态待确认时，按 AI 的提示选择，也可以在请求里直接说「用 Firefox 的店铺 A」。

接着验证这份连接能打开网页。在同一个会话中发送下面这句话。

> 用九头虫 MCP 在已连接的浏览器中打开 https://doc.jtcrpa.com/practice/index.html 。告诉我实际打开的网址。

确认浏览器里出现书店练习场后，再往下做。如果 AI 提示「当前连接尚未提供此页面工具」，按[本页的排查步骤](#遇到问题)处理。

## 3. 试采书店首页

### 查看网页并保存工作流

在同一个 AI 会话中发送下面这段话。本例只采首页，方便核对结果。

> 用九头虫 MCP 采集刚才打开的书店首页。每本书一行，采集书名和价格，列名用 title 和 price，保留货币符号。先给我看几行试采结果，再保存为「书店 MCP 练习」工作流，运行时写入 bookshop_demo 数据集。告诉我工作流编号，等我确认后再运行。

AI 报告保存成功后，可以在扩展的「**主工作台**」搜索「书店 MCP 练习」核对。目标标签页会保留，方便下一步运行。

### 确认运行并查看结果

确认试采结果符合预期后，单独发送下面的消息。

> 确认运行「书店 MCP 练习」，在刚才的书店首页执行。等运行结束，告诉我本次写入了几行，再读取 bookshop_demo 数据集，用表格显示 title 和 price。

首页首次运行且数据集为空时，应写入 4 行。也可以在扩展的「**数据存储**」找到 `bookshop_demo`，点击「**预览**」核对。

| title | price |
| --- | --- |
| 山海之间 | ¥32.00 |
| 城市慢行 | ¥45.00 |
| 生活的留白 | ¥39.00 |
| 月光落在书页上 | ¥28.50 |

下次可以在书店点击「**下一页**」，再让 AI 用已保存的工作流采集第 2 页。若只想看之前保存的数据，可以直接请 AI 读取 `bookshop_demo`。[数据存储与数据预览](/data/storage-preview)

## 使用启动参数或从接口试采

- **带参数启动。** 在对话中说「运行『书店采集』，本次关键词用『旅行』，采集页数填 3」。请使用该工作流已有的参数名称。工作流会使用本次值，未填写的参数可沿用它的默认值。[参数节点与启动参数](/automation/workflow-parameters)
- **从网页接口试采。** 在目标网页做一次加载操作，再请 AI 检查该页加载的数据、查看响应样例并试采所需字段。[从网页加载的数据中采集](/tutorial/from-api)

## 管理浏览器连接 {#manage-connections}

要添加另一份浏览器配置，在对应浏览器或个人资料里打开「**MCP 连接**」，开启开关并按页面提示完成接入。下次在客户端发起任务时，直接说要用哪一份浏览器配置。继续翻页或查询刚才的运行时，AI 会沿用原任务选中的浏览器。想换浏览器时，明确说明新的目标。

升级前已使用浏览器专用配置的客户端可以继续使用原服务。想将这份浏览器加入通用服务时，在它的「**MCP 连接**」页关闭再开启开关。需要给客户端固定一份浏览器时，使用「**复制当前浏览器专用配置**」。

| 需要做什么 | 操作 |
| --- | --- |
| 暂停当前浏览器的 MCP 访问 | 关闭该浏览器里的「**开启 MCP 连接**」。再次开启可恢复有效的连接。 |
| 查看登记的连接 | 在终端运行 `jtcrpa-mcp list`，核对浏览器和连接编号。 |
| 移除一条连接 | 运行 `jtcrpa-mcp remove`，按提示选择连接并确认。对应的在线会话会断开。 |
| 清空所有连接 | 运行 `jtcrpa-mcp clear`，立即撤销全部连接登记并断开在线会话。桥接器仍可用于重新接入。 |

浏览器打开时也可以移除或清空连接。Windows 的 PowerShell 若提示禁止运行脚本，将命令中的 `jtcrpa-mcp` 改为 `jtcrpa-mcp.cmd`。

要恢复访问，在目标浏览器的「**MCP 连接**」页点「**重新接入**」，按提示运行新的接入命令。通用配置可继续使用，原专用配置需重新复制并替换。

## 遇到问题

| 看到的情况 | 怎么处理 |
| --- | --- |
| 设置菜单里找不到「MCP 连接」 | 检查是否装的是九头虫 Agent，并确认当前扩展版本支持 MCP。需要获取支持 MCP 的版本时，可[联系九头虫](https://jtcrpa.com/contact)。 |
| 页面显示「等待运行终端接入命令」 | 保持这个浏览器打开，在本机终端运行从该页面刚复制的整条接入命令。若终端找不到 npm，安装 Node.js 后重新打开终端，再复制页面提供的安装命令。 |
| 扩展提示本机通信接口尚未就绪 | 等正在运行的工作流结束，保存并关闭工作流编辑页。若界面仍提示手动重载，打开浏览器的扩展管理页，重新加载九头虫 Agent 后再回来确认状态。 |
| 浏览器已连接，AI 仍找不到九头虫工具 | 核对服务是否已添加到正在使用的本机客户端，保存后重启客户端，再在新会话中请 AI 列出标签页。 |
| 能列出标签页，但提示「当前连接尚未提供此页面工具」 | 确认目标浏览器里的九头虫 Agent 与本机桥接器是配套版本。更新两端后，重新开启「MCP 连接」，重启 AI 客户端，再试一次打开书店。如果仍提示缺少页面工具，可[联系九头虫](https://jtcrpa.com/contact)确认配套版本。 |
| 只出现「复制 MCP 配置」 | 这份浏览器仍使用专用 MCP。确认两端已更新后，在浏览器的「MCP 连接」页关闭再开启开关，按提示接入通用服务。 |
| AI 列出的是另一个浏览器的标签页 | 在对话里指定目标浏览器名称。找不到目标时，在那个浏览器的「MCP 连接」页确认已授权且保持打开。 |
| 提示 `BROWSER_RECOVERING` 或「正在恢复浏览器连接」 | 保持目标浏览器打开，等「MCP 连接」页恢复到「浏览器与本机程序已连接」后重试。若刚才已经启动工作流，先在原浏览器查这次运行的状态，再决定是否重跑。 |
| 提示「需要重新接入」 | 点击「重新接入」，再复制并运行新的接入命令。[管理浏览器连接](#manage-connections) |
| 已保存工作流，找不到采集结果 | 先确认已在会话里同意运行，再请 AI 核对本次运行状态、写入行数和最近日志。运行成功但写入 0 行时，核对目标页面并重新试采。已有写入时，核对数据集名称。[执行日志](/automation/run-logs) |
