# 遇到问题先看这里

先看你现在遇到的现象。无需先看懂所有报错，也不用重新安装扩展。

| 你遇到的情况 | 去哪里处理 |
| :--- | :--- |
| 图标找不到、刚装好不能使用 | [安装与首次使用](/guide/install) |
| AI 在分析，或出现登录、权限等卡片 | [AI 准备任务时会发生什么](/guide/during-compile) |
| 一条没采到，或少了很多内容 | [采不到数据怎么办](/troubleshooting/empty-result) |
| 中途停住，有恢复或结束按钮 | [运行中断了怎么办](/troubleshooting/interrupted) |
| 提示网页不支持或需要刷新 | [页面不支持操作](/troubleshooting/page-not-supported) |
| 条数不对、有旧列名、重复或混入旧数据 | [检查采集结果](/data/check-results)与[整理结果](/data/tidy-results) |
| 导出的文件打不开、数字格式不对 | [导出数据](/data/export) |
| 定时任务没有按时启动 | [定时任务](/automation/scheduled-task) |
| 长时间运行变慢，网页似乎不动 | [防止电脑与网页休眠](/troubleshooting/anti-sleep) |
| 邮件没有收到 | [工作流邮件提醒](/automation/notifications) |
| 看不懂提示中的词 | [提示信息对照表](/troubleshooting/error-reference) |

## 先记录现象，再修改

打开工作流的「**日志**」，选择出问题的那次运行，看看最后在处理哪个网页、有没有等待你操作。已经写入或提交的内容可能保留，尤其是填写表单、发送数据的任务，重新运行前先检查。

想让 AI 修正时，从原工作流的「**修改**」进入，直接说看到的问题，例如：“第二页没有采到，帮我看看。”不用自己猜技术原因。

## 需要反馈时，准备这些

在侧边栏底部「**联系方式**」找到反馈入口，提供：

- 你当时发送的采集需求，以及网页地址。
- 期望得到什么，实际得到什么；能举一条记录最好。
- 出问题的时间、扩展版本和浏览器名称。
- 对应那次运行的日志文件：在[执行日志](/automation/run-logs)中点击「**导出 .log**」。

发送前检查日志和截图里的账号信息、页面内容及密钥，去掉不适合分享的部分。无需提供账号密码。
