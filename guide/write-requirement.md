# 采集需求怎么写

需求描述得越清晰，AI 编出的工作流越稳定。写需求不需要任何技术背景，你只需向它描述清楚“你想要什么结果”。

## 一、优先使用内置模板（最省心）

在「AI 编译生成」的新对话中，「试试这样说」提供 6 个快捷模板。点击后会填入一条示例需求，可以继续修改：

| 模板名称           | 适用场景                                           |
| :----------------- | :------------------------------------------------- |
| **「采集商品列表」** | 采集当前页面的商品列表 |
| **「翻页采集文章」** | 逐页采集列表内容 |
| **「批量采集文章详情」** | 根据文章列表采集详情页 |
| **「滚动采集用户评论」** | 页面向下滚动时加载更多内容 |
| **「接口采集商品列表」** | 尝试从网页加载的数据中采集商品列表 |
| **「能做什么」** | 了解功能 |

## 二、万能需求公式与核心四要素

如果你需要自己编写需求，请牢记这条**万能公式**：

> **`【目标字段】 + 【翻页/滚动方式】 + 【停止条件】 + 【数据清洗（可选）】`**

### 1. 目标字段：指明具体列名

- ❌ 模糊表述：“把上面的商品信息采下来”
- ✅ 清晰表述：“采集商品的**标题、当前价格、原价、月销量、店铺名称**”

### 2. 目标页面：先打开，再说话

- AI 是结合你**当前激活的标签页**来阅读界面的。写需求前，请确保浏览器正停留在目标网页上。

### 3. 停止条件：明确何时结束（最易遗漏）

- 如果不交代何时停止，AI 可能只处理当前页，也可能理解成其他范围；最好明确说明。
- 常见写法：“**翻满 5 页停止**”、“**直到最后一页**”、“**向下滚动 10 次或直到没有新内容**”。

### 4. 数据清洗：注明特殊处理

- 例如：“**价格去掉货币符号 ¥**”、“**只保留销量大于 500 的商品**”、“**提取出完整网址**”。

### 补充：页面慢，别只写死秒数

这不属于上面四要素，但很常见：如果页面要等一会儿才刷出内容，
可以按「某块内容出现/消失」来等，比固定写「等待 3 秒」更准。

> 等商品列表加载出来再开始采集，最多等 15 秒。

它会在目标一出现时就继续；超过上限还没出现，才会记为「页面未就绪」。
详见[等页面加载完成再采集](/tutorial/wait-page)。

## 三、常用范例（可直接复制套用）

- **标准多页翻页采集**  
  `采集当前列表的商品标题、价格和销量，自动点击“下一页”，共采集 5 页数据。`
- **瀑布流滚动加载**  
  `滚动加载采集列表里的所有帖子标题和作者，直到向下滚动不再出现新数据为止。`
- **列表进详情页抓取（二级页面）**  
  `先采集当前列表所有文章的标题和链接，再依次点进详情页抓取正文和发布时间。`
- **带过滤与格式清洗**  
  `采集商品标题和价格，价格那一列去掉前面的“¥”字符，且只保留价格在 100 元以上的数据。`
- **页面加载慢**  
  `等商品列表加载出来再开始采集，最多等 15 秒。`
- **先填表再采集**  
  `在搜索框输入「机械键盘」，把排序选成「销量」，勾上「只看有货」，点「搜索」，等结果列表出来再采集前 2 页的标题和价格。`
- **长期比价准备**  
  `采集当前页面的商品名称和实时售价，后续我需要每天定时启动该任务对比价格波动。`

## 四、常见误区与避坑

| 常见误区                   | 为什么会出错                                     | 应该怎么改                                                           |
| :------------------------- | :----------------------------------------------- | :------------------------------------------------------------------- |
| **字段太笼统**             | 仅写“采数据/抓信息”，AI 无法确定你要提取哪些列   | 把需要保留的列名逐一列出                                             |
| **一句话塞入多重无关任务** | 同时要求采集 A 网站列表并跨站对比 B 网站         | 拆分成两个独立的工作流，每次专注于一个页面                           |
| **漏写停止条件**           | AI 可能无法判断采集范围                         | 主动加上“共抓取 N 页”或“直到没有下一页”                              |
| **描述过于复杂**           | 细节太多反而让目标不清楚                         | 先说明要采什么、从哪里采，以及什么时候停止                             |

## 五、写错或漏填如何补充

如果在初次生成后发现遗漏了字段，**不需要删掉重来**。直接在对话框中像日常聊天一样继续补充说明：

> “帮我把店铺评分这一列也加上”  
> “价格那一列去掉单位‘元’”

AI 会在上一轮编译的基础上自动更新规则并重新保存。

::: tip 改的是哪一个工作流？
上面这种补充，改的是**刚刚这一轮对话里编出来的那个工作流**。

如果你想改的是**早就编好、已经躺在「主工作台」里的那个**，做法不太一样——
可以从卡片点击修改，也可以在输入框**最前面**用 `@` 选择它。步骤见
[修改已有工作流](/guide/modify-workflow)。
:::
