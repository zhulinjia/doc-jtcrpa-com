# 采集需求怎么写

需求描述得越清晰，AI 编出的工作流越稳定。写需求不需要任何技术背景，你只需向它描述清楚“你想要什么结果”。

## 一、优先使用内置模板（最省心）

在「AI 编译生成」页面的输入框上方，提供有 7 种常见场景的快捷模板。点击即可载入标准描述：

| 模板名称           | 适用场景                                           |
| :----------------- | :------------------------------------------------- |
| **「电商列表」**   | 采集商品列表（商品名、券后价、销量、店铺等）       |
| **「文章列表」**   | 采集资讯或博客列表（标题、作者、发布时间、摘要）   |
| **「评论列表」**   | 抓取商品或动态下的用户评论、星级评分与发表时间     |
| **「翻页提取」**   | 列表带有分页按钮（如「下一页」或页码），需跨页抓取 |
| **「滚动加载」**   | 瀑布流页面（向下滚动才会加载新内容），自动滚到底部 |
| **「子页面抓取」** | 列表本身信息不全，需要逐个点进详情页提取正文与大图 |
| **「能做什么」**   | 初次了解功能时的咨询提问                           |

## 二、万能需求公式与核心四要素

如果你需要自己编写需求，请牢记这条**万能公式**：

> **`【目标字段】 + 【翻页/滚动方式】 + 【停止条件】 + 【数据清洗（可选）】`**

### 1. 目标字段：指明具体列名

- ❌ 模糊表述：“把上面的商品信息采下来”
- ✅ 清晰表述：“采集商品的**标题、当前价格、原价、月销量、店铺名称**”

### 2. 目标页面：先打开，再说话

- AI 是结合你**当前激活的标签页**来阅读界面的。写需求前，请确保浏览器正停留在目标网页上。

### 3. 停止条件：明确何时结束（最易遗漏）

- 如果不交代何时停止，AI 默认只会处理当前显示的一页内容。
- 常见写法：“**翻满 5 页停止**”、“**直到最后一页**”、“**向下滚动 10 次或直到没有新内容**”。

### 4. 数据清洗：注明特殊处理

- 例如：“**价格去掉货币符号 ¥**”、“**只保留销量大于 500 的商品**”、“**提取出完整的绝对跳转链接**”。

## 三、常用范例（可直接复制套用）

- **标准多页翻页采集**  
  `采集当前列表的商品标题、价格和销量，自动点击“下一页”，共采集 5 页数据。`
- **瀑布流滚动加载**  
  `滚动加载采集列表里的所有帖子标题和作者，直到向下滚动不再出现新数据为止。`
- **列表进详情页抓取（二级页面）**  
  `先采集当前列表所有文章的标题和链接，再依次点进详情页抓取正文和发布时间。`
- **带过滤与格式清洗**  
  `采集商品标题和价格，价格那一列去掉前面的“¥”字符，且只保留价格在 100 元以上的数据。`
- **长期比价准备**  
  `采集当前页面的商品名称和实时售价，后续我需要每天定时启动该任务对比价格波动。`

## 四、常见误区与避坑

| 常见误区                   | 为什么会出错                                     | 应该怎么改                                                           |
| :------------------------- | :----------------------------------------------- | :------------------------------------------------------------------- |
| **字段太笼统**             | 仅写“采数据/抓信息”，AI 无法确定你要提取哪些列   | 把需要保留的列名逐一列出                                             |
| **一句话塞入多重无关任务** | 同时要求采集 A 网站列表并跨站对比 B 网站         | 拆分成两个独立的工作流，每次专注于一个页面                           |
| **漏写停止条件**           | 结果只抓了一页就停下了，容易误以为功能失效       | 主动加上“共抓取 N 页”或“直到没有下一页”                              |
| **使用过多技术代码词汇**   | 试图向 AI 描述 CSS 选择器、XPath 或 DOM 节点结构 | 无需写技术术语；像给新助理布置任务一样，只描述你要的**最终数据**即可 |

## 五、写错或漏填如何补充

如果在初次生成后发现遗漏了字段，**不需要删掉重来**。直接在对话框中像日常聊天一样继续补充说明：

> “帮我把店铺评分这一列也加上”  
> “价格那一列去掉单位‘元’”

AI 会在上一轮编译的基础上自动更新规则并重新保存。

::: tip 改的是哪一个工作流？
上面这种补充，改的是**刚刚这一轮对话里编出来的那个工作流**。

如果你想改的是**早就编好、已经躺在「主工作台」里的那个**，做法不太一样——
要在输入框**最前面**用 `@` 把它点名出来。步骤和三个容易踩的坑见
[修改已有工作流](/guide/modify-workflow)。
:::
