# 通过 HTTP 请求发送数据

采集到的数据可以发送给另一个系统。比如，采集商品名称和价格后，发送到公司的业务系统。

下面先用一个练习网站和一个测试地址，做一次「采集书名和价格，再发送出去」。

::: tip 这是一次练习
练习中的书籍数据是公开的，发送地址是第三方测试服务，不会保存到你的业务系统。请不要把个人信息或真实业务数据发送到这个测试地址。
:::

## 1. 打开练习网页

在浏览器中打开[书籍练习网站](https://books.toscrape.com/)。这是一个英文书籍列表页面，书名下方可以看到价格。

## 2. 写下需求

停留在书籍列表页面，点击浏览器工具栏上的九头虫图标，进入「**AI 编译生成**」，复制并发送下面这段话：

> 采集当前页面第一本书的书名和价格，保存到数据存储。然后通过 HTTP 请求，用 POST 方式将这一条数据发送到 `https://httpbin.org/post`，发送格式为 JSON，字段分别叫「书名」和「价格」。
>
> 测试地址会把收到的数据放在返回结果的 json 字段里。请把其中的书名和价格单独保存到另一份数据集，方便我核对。如果请求失败，请暂停并提示我处理。

这个地址是用来测试请求的，会返回收到的内容。它不是你的业务系统地址。

## 3. 启动工作流

等待 AI 分析编译。保存完成后，打开「**主工作台**」，找到刚生成的工作流，点击「**手动启动**」。

## 4. 检查结果

运行结束后，打开「**数据存储**」，点击数据集的标题进入预览。找到采集到的书名、价格，再查看另存的返回数据，核对两边是否一致。两张卡片标题可能相同，可以看标题下方的小字标识来区分。

例如，练习网站当前第一本书是 **A Light in the Attic**，价格是 **£51.77**。采集结果和返回结果里都应能看到相同的书名和价格；网站内容可能发生变化，以页面实际显示为准。

如果没有看到返回数据，点击工作流卡片上的「**查看运行日志**」，找到发送请求的那一步，**点击这一行展开详情**，查看「结果」中的提示。日志显示「请求成功」只说明请求得到了成功响应；发送的书名和价格是否正确，还要对照返回数据。

如果数据不对或没有保存返回内容，可以在[修改已有工作流](/guide/modify-workflow)中告诉 AI 哪一步需要调整，再试一次。

::: warning 工作流完成不等于发送成功
如果发送步骤遇到错误，工作流可能仍会继续。请核对接收方返回的内容和日志；超时后重试前，也要注意接收方是否已经收到，避免重复发送。
:::

## 换成自己的业务系统

练习通过后，可以在工作流卡片上点击「**在聊天中修改此工作流**」，让 AI 改用你的业务系统地址。

修改前，向接收方确认**接口地址、发送方式、需要的字段和验证要求**，再把这些信息告诉 AI。建议先发送少量测试数据，确认对方收到且内容正确后，再改成正式数据。

如果接收方只支持网页登录，请先询问其他验证方式：HTTP 请求不会自动带上浏览器的登录状态。地址和验证信息会交给所选 AI 服务，分享工作流或日志前也请检查是否包含敏感内容。
