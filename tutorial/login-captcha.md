# 登录、验证码与人工介入

采集过程中遇到登录失效、滑块验证码或频率风控拦截时，会**安全挂起并等待人工处理**。本篇说明处理机制与应对策略。

::: tip 核心机制说明
**扩展绝不强行盲撞风控。**  
遇到需要人类证明身份的场景，扩展会主动暂停任务，保留已采集好的数据，等待你手动解决后点「恢复」继续。扩展**不会**、也无法私自破解验证码。
:::

## 三种常见的打断情形与处理

### 1. 页面提示需要登录

- **预防方案（最省事）**：启动采集前，**先在浏览器中正常把目标网站登录好**。在有效登录态下执行，通常全程畅通。
- **进阶写法**：如果担心跑着跑着 Token 过期，可在需求中加上约定：
  > 采集过程中如果弹出登录拦截，停下来等我登录。

### 2. 弹出滑块或点选验证码

当网站触发人机核验时，任务会**自动挂起（暂停）**：

- 侧边栏里那张卡片的状态会变为 **「已挂起：等待处理」**。
- 当前网页右下角会出现浮层提示：**「运行已暂停，等待你处理」**。
- 浏览器会同步弹出系统通知。

**正确处理步骤**：

1. 切到目标网页，像平时一样**手动完成验证码滑块或点选**。
2. 确认网页恢复正常内容后，切回右侧边栏。
3. 点击卡片上的 **「恢复」** 按钮，任务将从断点处继续往下采集。

### 3. 被系统风控提示“访问过于频繁”

- **处理方式**：降低采集请求频次。在编写需求时主动加上节奏控制：
  > 每次翻页后随机等待 3 到 5 秒。

## 任务挂起时的三枚控制按钮

任务因异常暂停时，卡片上会提供三枚操作按钮：

| 按钮     | 实际作用                           | 何时使用                                             |
| :------- | :--------------------------------- | :--------------------------------------------------- |
| **恢复** | 从中断的步骤无缝继续运行           | **最常用**。当你已经手动过完验证码或处理好网页后点击 |
| **跳过** | 放弃当前这一步，直接强行进入下一步 | 当前单条数据卡死无法加载，且该条放弃不影响全局时     |
| **结束** | 立即彻底终止本次采集任务           | 不想继续跑了。已抓取到的历史数据会被保留在数据存储中 |

::: warning 慎用「跳过」按钮
点击「跳过」意味着当前这页（或这条详情）的数据**彻底不采了**。若后续步骤依赖本步的结果（如没有拿到链接就无法打开内页），跳过可能引发连锁失败。**能用「恢复」就优先使用「恢复」**。
:::

## 运行控制关键术语辨析

| 状态/操作        | 出现阶段                                      | 含义解释                                                 |
| :--------------- | :-------------------------------------------- | :------------------------------------------------------- |
| **中断（暂停）** | 任务正常**运行中**可随时手动点击              | 临时主动停下，浏览器保留当前进度，可随时点「恢复」继续   |
| **已挂起**       | 遭遇异常（验证码/网络卡顿）时**系统自动触发** | 任务暂停并等待你手动处理现场，处理完后点「恢复」         |
| **结束**         | 运行中、挂起中均可点击                        | 彻底终止运行。终止后不可断点续跑，但已抓取的数据完全保留 |

## 需求预设防打断技巧

在编写采集需求时附带以下提示词，能大幅降低被打断的概率：

- **应对加载慢的网页**：`每次翻页后等待 3 秒`
- **应对严格风控的平台**：`每次翻页后随机等待 4-6 秒`
- **应对登录态易过期的网站**：`如果检测到未登录状态，暂停任务等待我登录`
- **应对详情页较重的站点**：`打开详情页后等待 2 秒再提取正文`
