# 执行日志

日志记录一次运行做过哪些步骤。结果不对、任务停住，或需要反馈问题时，用它找到对应位置。

## 打开出问题的那一次

在「**主工作台**」找到工作流，点击卡片的「**日志**」（鼠标悬停提示「查看运行日志」）。定时任务卡片也有日志入口，打开后会进入新的浏览器标签页。

页面顶部标题是「**执行日志**」。先用下拉选择器选对工作流和运行时间，避免把昨天的成功记录当成本次结果。

## 第一次先看这三件事

1. **状态**：运行中、已暂停、已完成或已失败？“已完成”后还需要核对数据。
2. **最后在做什么**：停在打开网页、等待内容、采集，还是发送数据？
3. **提示原因**：是否要求登录、开启权限，或说明页面未响应？先按具体原因处理。

有一条红色异常，不一定表示整个任务失败；有些步骤出错后仍会继续。反过来，任务完成也可能漏掉被跳过的内容。最终用[结果检查](/data/check-results)确认。

## 需要细节时再展开

有详细内容的行可以点击「**展开详情**」，查看「参数」和「结果」，也可以复制。长日志只先显示一部分，用「**加载更早的 N 行**」继续查看。

不理解其中的技术内容时，无需自行修改，把出错时间和相关行保留下来即可。常见提示见[对照表](/troubleshooting/error-reference)。

## 导出日志反馈问题

点击「**导出 .log**」保存本次完整日志，再附上采集需求、网页地址和实际现象。发送前检查是否含账号信息、网页内容或验证信息。

「删除此运行日志」删除当前记录；「清空日志」按当前页面范围清除可删除的记录，确认前先看说明。正在执行或挂起的运行不能这样删除。日志删除后不可恢复，排查问题时先导出留存。
